## What was done

### 1. A crash between the click and the observation is now covered

`tests/integration/test_crash_recovery.py`, eight tests. This closed the gap
`docs/STATUS.md` named: the window after the final control is used and before an
independent observation exists.

The crash is simulated with a `BaseException` subclass, not an `Exception`,
because every error path in `ExecutionWorkflow` catches `Exception`. An
`Exception` would have been caught and reported as `UNKNOWN_STATE`, which would
have tested the opposite claim.

Pinned: the durable record stays `REQUESTED` with no result and no
`order_reference`; a proved fill whose result never reached disk is still not
recorded as `ACCEPTED`; a restarted process refuses the same signal as a
duplicate before the order dialog opens; the refused retry cannot overwrite the
pending record; only `reconcile` settles it; a snapshot written before a
terminal restart is refused as stale.

**It found a real defect.** `workflow.py:58` never passed the state to
`_record`, so the structured `state` field in `audit.log` was `null` for every
transition and the dashboard's State column was permanently empty. Fixed.

### 2. Counters and phase latency

`src/auto_trade/application/metrics.py`. Six phases measured between two states
the application records. Exposed as `metrics`, `GET /api/metrics`, and
`metrics.json` in the diagnostics bundle.

The design decision matters more than the feature: metrics are **derived from
`audit.log` on demand**, not collected in memory. An in-process counter would
report a clean, empty, healthy-looking summary for exactly the run that died
between the click and the observation, which is the run whose timing matters.

Deliberate, each with a test: an unmeasured phase reports `null` and
`measured: false` and never zero; an attempt that used a final control and
recorded no result is counted as `unresolved`; a refusal is not unresolved; a
truncated log says so; an unparseable line is counted rather than dropped; a
backwards clock produces no interval rather than a negative duration; **no
threshold or alert was added**, because a latency figure must never be able to
look like a verdict on an outcome.

Verified against a real `AuditLogger` and a real `ExecutionWorkflow`, with
injected delays that the reported figures then matched. The dashboard's render
path was checked separately with `node --check` and a direct execution of the
render function, since no test runs JavaScript.

### 3. Persian documentation for the safety-relevant pages

Nine pages under `docs/fa/`, each linking to its English counterpart, with both
READMEs indexing both languages.

`tests/unit/test_documentation.py` makes the pair list a contract: a page must
be either translated or exempted with a written reason, so a new page cannot
fall through both lists. It also fails on a missing cross-link, a dropped safety
section, a mistyped control identifier, a gate added on one side of the
execution tables only, or a relative link that does not resolve.

**It found four real problems:** three pages with no way back to their
translation; `STRATEGY_INTEGRATION.md` in neither list; twenty-two links inside
`docs/fa/` pointing at `docs/fa/fa/`; and a Persian claim that the close path
was not implemented, which it was.

## What was deliberately not done

- No live or funded account was used, and none is in scope at any step.
- No hedge, partial close, or modify. Each needs its own measured control
  identifiers and its own verification of the resulting state.
- No threshold or alert on any latency figure.
- No automatic recovery action. Every path that changes an account here is
  operator-initiated and independently observed.
