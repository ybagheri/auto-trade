# یکپارچه‌سازی استراتژی

چگونه یک کتابخانه‌ی تحلیل بازار به پل متصل می‌شود. کتابخانه تصمیم می‌گیرد **چه چیزی** معامله شود؛ پل تصمیم می‌گیرد **آیا اصلاً مجاز است یا نه**.

## نقطه‌ی اتصال

یک استراتژی هر شیئی است با یک `name` از نوع string و یک متد `evaluate`:

```python
class MyStrategy:
    name = "my-strategy"

    def evaluate(self, context: StrategyContext) -> TradeSignal | None: ...
```

`evaluate` یک `TradeSignal` برمی‌گرداند، یا یک mapping که `TradeSignal.from_dict` می‌پذیرد، یا `None` برای «در حال حاضر معامله‌ای نیست».

`StrategyContext` عمداً فقط‌خواندنی و عمداً کوچک است:

| فیلد | معنا |
| --- | --- |
| `symbol` | نمادی که در حال ارزیابی است، با حروف بزرگ |
| `now` | زمان فعلی دارای timezone |
| `positions` | پوزیشن‌های مشاهده‌شده، یا تاپل خالی وقتی مشاهده‌ی پوزیشن در دسترس نیست |
| `account` | snapshot حساب، وقتی در دسترس باشد |
| `open_positions_for` | فیلتر راحتی برای `symbol` |

یک استراتژی نمی‌تواند به ترمینال، دفتر اجرا، موتور ریسک یا لاگ حسابرسی دسترسی داشته باشد. نمی‌تواند سفارشی ثبت کند. نکته همین است: یک کتابخانه‌ی شخص ثالث پیشنهاد می‌دهد، و پل تصمیم می‌گیرد.

## وصل کردن آن

فایل را در پوشه‌ی `strategies/` پروژه بگذارید و `AUTO_TRADE_STRATEGY` را به `module:attribute` اشاره دهید:

```dotenv
AUTO_TRADE_STRATEGY=my_strategy:build
```

`strategies/example_strategy.py` یک مرجع کارآمد است. آن را کپی کنید و بدنه را جایگزین کنید.

پوشه‌ی `strategies/` وجود دارد چون یک مفسر سخت‌شده `sys.path` را قفل می‌کند و `PYTHONPATH` را نادیده می‌گیرد، پس ماژولی که آنجا رها شود بدون نصب چیزی importable است. ماژولی که از پیش نصب شده یا به شکل دیگری importable است، همان‌طور که هست استفاده می‌شود.

`attribute` می‌تواند یکی از این دو باشد:

- یک **factory بدون آرگومان** که یک استراتژی برمی‌گرداند، یا
- یک **نمونه‌ی آماده** که از پیش `evaluate` را پیاده کرده است.

یک تابع ساده مانند `def decide(context)` هدف معتبری نیست، چون بدون آرگومان فراخوانی می‌شد. loader این را تشخیص می‌دهد و می‌گوید. به‌جای آن آن را بپیچید:

```python
from auto_trade.application.strategy import CallableStrategy

def build() -> CallableStrategy:
    return CallableStrategy(my_library.decide, name="my-library")
```

## درخواست یک تصمیم

```powershell
python -m auto_trade evaluate --symbol BITCOIN
```

این فرمان در صورت در دسترس بودن، context را با مشاهده‌ی پوزیشن می‌سازد، استراتژی را صدا می‌زند، و:

- وقتی استراتژی پیشنهادی نمی‌دهد، چیزی نمی‌نویسد و با `"decision": "NO_SIGNAL"` و کد `0` خارج می‌شود؛
- وقتی یکی پیشنهاد می‌دهد، فایل سیگنال می‌نویسد و یک رویداد حسابرسی ثبت می‌کند؛
- اگر استراتژی بارگذاری نشود یا خطا بدهد، با کد `1` و همان دلیل خارج می‌شود؛
- اگر هیچ استراتژی پیکربندی نشده باشد، با کد `2` خارج می‌شود.

سیگنال در `AUTO_TRADE_SIGNAL_DIR` می‌نشیند و سپس دقیقاً مثل هر سیگنال دیگری پردازش می‌شود. **یک کتابخانه نمی‌تواند مجوزهای خودش را گسترش دهد**: یک `EURUSD` پیشنهادی همچنان وقتی whitelist فقط `BITCOIN` دارد رد می‌شود.

## ترتیب اختیار

1. استراتژی پیشنهاد می‌دهد. هیچ توانی برای عمل کردن ندارد.
2. موتور ریسک اعتبارسنجی می‌کند: فهرست مجاز، حجم، انقضا، تکراری‌ها، نرخ.
3. workflow دیالوگ سفارش را آماده و یک baseline مشاهده‌شده ثبت می‌کند.
4. دروازه‌ی اجرا تصمیم می‌گیرد آیا اصلاً کلیک روی کنترل نهایی مجاز است یا نه.
5. دیالوگ دوباره خوانده می‌شود و باید همچنان با آنچه تأیید شده مطابق باشد.
6. کنترل کلیک می‌شود، که فقط به‌عنوان یک اقدام ثبت می‌شود.
7. مشاهده‌ی مستقل تصمیم می‌گیرد آیا واقعاً پوزیشنی ظاهر شد یا نه.

مرحله‌ای که شکست بخورد، توالی را متوقف می‌کند. مراحل ۴ تا ۷ هرگز استراتژی را مشورت نمی‌دهند.

## فعال‌کردن یک کنترل نهایی

اجرا رد می‌شود مگر آنکه `AUTO_TRADE_ENABLE_EXECUTION=true` صریحاً تنظیم شده باشد. هیچ مسیر پیش‌فرضِ فعالی ندارد. دروازه همچنین هنگام فعال بودن dry-run، هنگام درگیر بودن kill switch، وقتی سیاست فقط دمو برقرار نیست، وقتی هیچ baseline مشاهده‌شده‌ای وجود ندارد، و وقتی action درخواستی `BUY`/`SELL` نیست، رد می‌کند.

برای فهرست کامل دروازه‌ها و شناسه‌های کنترل اندازه‌گیری‌شده، [اجرا](EXECUTION.md) را ببینید.
